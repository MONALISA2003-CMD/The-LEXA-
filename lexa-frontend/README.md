# LEXA Frontend

A fresh React + TypeScript frontend foundation for LEXA, a connected business operating workspace for SMEs. The current milestone is intentionally local-first: business records persist in the current browser profile via IndexedDB, through a Dexie provider boundary.

> **Local-only notice:** This is not secure multi-user SaaS. Records do not synchronize across devices or staff. Clearing browser storage may remove local data. Sign-in, invitations, mobile-money processing, tax/URA submissions, server-enforced permissions, and live AI are not connected. Payment methods in sales are records of what the operator says was received; they do not initiate transfers.

## Implemented in this starter

- Responsive workspace shell and branch context.
- Workspace and branch setup/switching.
- Product catalogue with search and category capture.
- Stock adjustments/opening balance records with reasons and movement history.
- Checkout with cart, stock validation, payment recording, persisted sale lines and receipt reference.
- Sales history and sale detail.
- Traceable partial/full returns with stock reversal records and an optional locally recorded refund.
- Dashboard metrics derived from saved records, with links into supporting workflows.
- Typed provider contracts, local repositories, domain services, currency-safe integer minor-unit calculations, Dexie transactions, unit tests, and Playwright workflow scaffold.

## Requirements

- Node.js 24 LTS is the recommended runtime. Node 22.12+ satisfies the current Vite baseline, but keep CI/deployment aligned with the runtime tested by the team.
- pnpm is the intended package manager.

## Start locally

```bash
corepack enable
corepack prepare pnpm@latest --activate
pnpm install
pnpm dev
```

The exact dependency graph should be resolved and `pnpm-lock.yaml` generated by running `pnpm install` in an environment with registry access before committing or deploying. Do not treat the package manifest alone as a reproducible install lock.

## Validate

```bash
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e
```

For Playwright, install the browser once with `pnpm exec playwright install chromium`.

## Architecture

- `src/modules/` contains page-level workflow UI.
- `src/domain/` contains business rules and calculations.
- `src/data/contracts/` defines typed repository interfaces.
- `src/data/repositories/` exposes business-facing data operations.
- `src/data/local/` contains Dexie/IndexedDB implementation details only.
- `src/app/` holds route definitions, providers, workspace context and the application shell.

React components must not import Dexie directly. The domain services own rules for sale completion, inventory changes, and return accounting. The local database schema is versioned; future schema changes must use Dexie migrations rather than resetting user data.

## Current scope boundary

This is Phase 0 plus an initial retail transaction slice, not the full product roadmap. Purchasing, supplier reconciliation, expenses, reports, customer accounts, tax/compliance, forecasting, assistant responses, team chat and secure administration are not falsely presented as complete. They can be implemented after the master-record → stock → sale path is stable and tested.
