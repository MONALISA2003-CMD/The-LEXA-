# LEXA integrated purchasing, finance, payroll, reporting and administration release candidate

Date: 2026-11-03
Release status: **SOURCE RELEASE CANDIDATE; not a certified production-ready release.**

## What this source update implements

- Purchasing: keeps the existing typed, tenant-authorized supplier, purchase order, goods receipt, supplier invoice, approval, and recorded supplier-payment workflows. The purchasing and accounts payable panels now refresh connected business projections after writes and provide cross-module navigation.
- Financial records: preserves immutable, balanced double-entry journals for source transactions. Expense approval now accrues a payable; an approved expense becomes paid only through a distinct, externally-confirmed settlement event, which clears that payable. The selected expense category's active, tenant-owned expense ledger account receives the debit, rather than a generic fallback. Legacy expenses previously posted directly to cash cannot be paid again through the new settlement API.
- Bank reconciliation: adds typed, branch-scoped API reads and a real statement CSV intake, matching against unallocated, posted journal lines from the appropriate bank ledger account, and completion checks for outstanding movements and closing balances. The UI enforces currency minor units and separates branch-specific accounts from shared accounts to prevent cross-branch statement exposure.
- Employees and payroll: preserves existing staff, attendance, timesheets, leave, payroll calculation, and approval services. An approved payroll run's externally confirmed payment now atomically creates a balanced source-linked ledger journal: gross payroll expense debit; bank net-pay credit; and payroll withholding liability credit. This does not initiate bank or mobile-money transfers.
- Reports and graphs: dashboard and authoritative reports consume database-backed API projections, refresh after connected workflow writes, on focus and at conservative intervals. The ledger source audit now includes 15 operational source classes, including expense approvals/payments and payroll payments; it identifies missing or unbalanced postings.
- Administration and integrations: settings now checks the readiness endpoint's database status, exposes missing Sentry/OpenTelemetry configuration, and distinguishes running services from independently tested backups, workers, and third-party integrations. Existing platform export/backup/recovery safeguards remain in place; this patch does not claim to have tested a restore or configured an unavailable provider.
- Correct currency units: UGX cash-session amounts are interpreted as zero-decimal currency values, not multiplied or divided by 100.
- HR form reliability: after a failed mutation, form input stays visible. Successful mutations invalidate relevant employee/payroll and finance/dashboard projections.

## Controls kept in force

1. All finance, purchasing and payroll routes continue to pass the global tenant authorization guard, role-specific permissions and branch restrictions.
2. A financial journal is created in the same database transaction as the status change where supported; no asynchronous fake success message replaces a committed accounting record.
3. Every bank statement match is against a posted line of the selected control account; matched journal lines cannot be reused.
4. Accounts, tenant role switching, and row-level security remain enabled. No live data or database migrations were modified as part of this source patch.
5. Externally recorded payments are not payment processor charges or bank transfers; the business must confirm that the payment occurred.

## How to deploy the source

1. Upload the root-level ZIP to `MONALISA2003-CMD/The-LEXA-` main. `.github/` is intentionally absent so the existing repository import workflow is preserved. Missing npm lockfiles are generated by the cleanup step before `npm ci`.
2. Verify the ZIP import GitHub Actions job, which runs backend tests / contract checks / build and frontend build / Vitest. A green job is necessary but not sufficient.
3. Check Render deploy status and `/health/ready`, and Vercel deploy status; both must identify the same Git commit.
4. On an isolated staging database, test: supplier→PO→goods receipt→supplier bill→approval→external payment→posted ledger; draft expense→approval→liability→settlement→bank line; employee→attendance→payroll calculation→approval→external payment→ledger; statement CSV→match→reconcile; report values after every step.
5. Validate users who have read-only, branch-restricted, purchasing-only, payroll-only and finance permissions; check that disallowed records and buttons cannot be accessed through direct HTTP requests.
6. Perform encrypted backup / actual isolated restore dry run; test background workers, alert delivery and third-party integrations. Enable provider keys and operational services only after independently verifying them.

## Open gaps and dependencies

- Supplier/bank/payroll payment flows record **external payment evidence**; they do not actually send funds. Payment processor settlement and bank feed integrations need separate verified credentials and reconciliation strategies.
- Sentry and OpenTelemetry were unconfigured in the last observed production readiness response. Export/restore depends on independent object-storage credentials and an isolated restore environment.
- No populated sales/product dataset was present in the last production Neon check. Real graphs require actual posted transactions; zeros must remain zeros until facts exist.
- This ZIP cannot modify `.github` workflows. Add an authenticated Playwright + isolated Neon integration gate to GitHub Actions separately before automatic production promotion.
- One-business-per-account business identity changes, full onboarding simplification, and each of the 54 module screens must receive an independent end-to-end signoff. This source patch targets the five requested business capability areas; it is not evidence that all 54 are production-complete.
