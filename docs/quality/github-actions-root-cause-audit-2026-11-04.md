**Scope:** `MONALISA2003-CMD/The-LEXA-`, GitHub Actions source-import run `41770548027`, job `126378978649`, recent adjacent runs, and the supplied upload-ready source ZIP.

## Confirmed root cause of the linked job

The source-import workflow correctly imported the root-level ZIP, cleaned the repository, validated its canonical layout, installed backend dependencies, generated and validated the Prisma client, and executed **165 backend tests (all passed)**. It then failed at `npm run contract:check`. The OpenAPI coverage script listed **13 backend HTTP operations** that were implemented in NestJS controllers but absent from `lexa-frontend/openapi/backend-contract.yaml`:

- GET `/workspaces/{workspaceId}/branches/{branchId}/workstream6/projects/tasks`

**Fix:** Add those 13 operations, with method, route, path parameters, response codes and descriptions matching the active controllers.

## Additional OpenAPI audit findings

The previous contract also declared `/workspaces/{workspaceId}/branches/{branchId}/inventory/lots` twice (GET in one YAML mapping and POST in another). A YAML loader would silently discard one of them. The mappings have been merged. **22 operations** had non-unique `operationId` values, mostly caused by truncated autogenerated names in Finance and Inventory. Those identifiers now uniquely and meaningfully identify their individual operations. **91 paths** did not declare at least one required path-template parameter (affecting 107 operations). Path-level declarations now cover them.

The standard-library `backend/scripts/check-openapi-coverage.py` now also rejects duplicate OpenAPI path keys and operation identifiers. This prevents those silent specification regressions in future import runs.

## Upload guidance

1. Upload exactly one new root-level ZIP in a single commit to `main`. Do not upload an extracted folder or add `.github/` to the ZIP.
2. The archive must contain `backend/`, `lexa-frontend/`, `docs/`, `scripts/` at the archive root, plus the allowed root-level configuration files. It must not contain `node_modules/`, `dist/`, `.git/`, `.github/`, or another repository folder.
3. Do not delete/move the ZIP in the same commit: the workflow computes the changed ZIP filename then opens that path from the checkout. Deleting it yields `The selected archive is not a regular file.`
4. Wait for **both** `Test and build backend` and `Test and build frontend` to pass, followed by the source commit. Confirm deployment status separately from GitHub CI.
